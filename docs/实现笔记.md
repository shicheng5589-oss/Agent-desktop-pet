# Codex 桌宠（DeepSeek 鼠控版 Live2D）

一个贴在 Windows 桌面上的 Live2D 小宠物：它读的是 **Codex 自己的实时状态**，
所以 Agent 在思考、执行、等你确认，还是已经做完，你一眼就能看出来 —— 不用切回 Codex 窗口。

> **这份文件是工程实现笔记**，记录了这个桌宠是怎么做出来的、踩过哪些坑、怎么调试。
> 面向使用者的说明请看仓库根目录的 **[README.md](../README.md)**（安装、设置、性能、兼容性、常见问题都在那里）。

## 怎么用

1. 双击桌面上的 **「Codex 桌宠」** 快捷方式（或双击 `启动桌宠.vbs`，都不会弹黑框）。
2. 形象出现在屏幕右下角，站在最上层、不占任务栏。**窗口只有角色那么大**，不会挡住别的东西。
3. 操作方式（都可以在设置里调，见下）：

   | 操作 | 效果 |
   | --- | --- |
   | 鼠标靠近 | **眼睛 + 头部跟着你的鼠标转**，按"相对窗口中心的偏移比例"映射（不是固定像素偏移） |
   | **左键单击** | **摸头**：优先判定头部区域，会脸红 / 爱心眼，还会做个动作 |
   | **左键双击** | **换表情**：在模型的表情里循环切换，弹一个小提示告诉你换了哪个 |
   | 点在**底部三个图标**上 | 触发那里配好的功能（**单击**触发；双击也按单击算），右键则是那一项配的右键功能 —— 见下一节 |
   | **左键按住拖动** | 移动窗口（位移超过 5 px 才算拖动），每一次真实鼠标移动搬一次窗口，跟手不卡 |
   | **右键单击** | 弹出菜单：进度卡片 / 刷新卡片信息 / 摸头 / 换表情 / 随机动作 / 设置 / 切到 Codex / 切换卡片 Agent / 重新载入 / 退出 |
   | **右键按住拖动** | 也是移动窗口，并且**不会**弹出系统菜单 |
   | **鼠标滚轮** | 直接在角色上滚动 = 缩放桌宠，以窗口中心为锚点，不会跑偏 |
   | 点在透明边角 | 直接穿过去，不挡你点别的东西 |
   | 盯着它看几秒 | 偶尔会害羞（脸红 / 心跳） |

   > 右键菜单只有**点在角色像素上**才会弹 —— 点在透明处会穿过去，弹的是桌面自己的菜单，不会两个一起冒出来。

   > 只有**点在角色身上**才算互动；点在它周围的透明区域会直接穿过去，不会挡住你点别的东西。
   > 进度卡片是纯展示，所有按钮都在设置窗口里 —— 因为透明窗口是"分层窗口"，网页收不到鼠标点击，
   > 所以点击/拖动是桌宠程序自己读鼠标状态来处理的（这也是它现在能正常拖动的原因）。

   > **拖动实现说明**（试过三条路，最后一条才对）：
   > ① 独立线程按 144 Hz 调 `SetWindowPos`：分层窗口 + WebView2 反复合成，把系统鼠标都拖死；
   > ② `ReleaseCapture()` + `WM_NCLBUTTONDOWN/HTCAPTION` 交给系统移动循环：在这个窗口上会立刻返回（日志 `0.00s`）；
   > ③ 靠 `MouseMove` 事件搬窗口：这类窗口里鼠标移动事件可能只送到一两帧，所以拖不动。
   >
   > 现在用的是：**一个 15ms 的 UI 定时器**，每帧读"光标现在在哪 + 按键还按着吗"，
   > 直接算出窗口应有的位置（不依赖鼠标移动事件，也不起工作线程）。松手立即停止。
   > `pet.log` 会记录每次拖动的：用时、搬动次数与速率、窗口位置变化、渲染 FPS。

## 底部三个按钮：撤回 / 铅笔 / 橡皮擦

设置里新增独立的 **「底部按钮」** 分类，可选择两套方案，并为每个按钮的
**单击 / 右键**分别指定功能；每一项都有 **「无功能」**。

> 触发方式换过一次手：最早是单击，中间短暂试过双击，2026-09-25 起**又改回单击**
> （双击手感不好）。设置里现在只有「单击 / 右键」两列；换回单击时，原来配在双击上的
> 功能会自动搬到单击上，不用重新配（老配置文件迁移一次就会记下来，不会反复覆盖）。
> 图标上双击也不会变成没反应 —— 它会按单击处理。

* **桌宠编辑 / 恢复 / 清理**——打开设置、编辑模式、锁定位置、恢复默认、撤销表情、
  清空进度卡片、隐藏到系统托盘、暂时静音动画。
* **Codex 联动**——新建会话、切到 Codex、复制新任务名、把备注写入 Codex 输入框、
  打断任务、撤回输入、用新空白会话清空上下文、关闭 Codex 窗口。

所有功能触发后都会先弹出 **确认框**，只有点击「是 / 确认」才真正执行。
三个图标按**画在图上的实际位置**命中（撤回 ≈ 角色宽度 35%、铅笔 ≈ 46%、橡皮擦 ≈ 56%，
纵向为角色高度的 ~0.743–0.820，即中心 0.775 上收 0.032、下放 0.045）。
上下不对称是故意的：误触几乎都发生在图标**上方**那一截空白，所以上方收得更紧；
旧参数是上下各 0.075（命中带总高 15%），比图标本身高近一倍，点在上方空白也会触发。
横向半宽从 0.085 收到 **0.046**（图标本体约 ±0.037 + 一点容错）：相邻图标中心间距约 0.105，
于是两块命中区中间留出 ~0.013 的空隙 —— 点在两个图标之间的空白不再算按钮（旧值 0.085 时
两块命中区大面积重叠，整条横带都按"最近的那个"算）。
所有 TOOL_MARK_* 都是**相对角色包围盒**的比例，放大/缩小桌宠时包围盒等比变化，命中区自动跟随。
点击图标不会误触发摸头、换表情或普通右键菜单；
点画纸空白处、写字板或身体则还是桌宠自己的反应。

> 之前的命中区是"把角色宽度三等分"，可那三个图标挤在中间偏左，
> 于是点最左边的**撤回**会落进中间那一格，弹出"铅笔：未配置功能"——现在按实测位置命中，不会再串格。
## 进度卡片：画在桌宠窗口里（宽度固定、高度自适应）

卡片**直接画在桌宠自己的网页里**（一个 div），不再单独开窗口：

* **尺寸**：宽度 CSS 固定 372px，**高度 `auto` 由内容撑开**（标题、数据行、正在做什么、最近一句话）。
  桌宠窗口尺寸**永远不变** —— 没有改窗口尺寸的卡顿，也不影响点击穿透。
* **位置**：固定在桌宠窗口上方、水平居中；打开时角色自动缩小一点腾位置（只改模型缩放，不动窗口）。
  * 新版改成**贴着"角色头顶"定位**：桌宠放大缩小时，卡片与头顶的距离**保持不变**。
    以前是贴窗口顶部，一放大中间就空出一大段，看着像卡片飘走了。
  * 默认间距 **12px**，设置里可调 **-20–60px**；负数会让卡片稍微压进头顶上方的留白，适合更紧凑的构图。
  * 卡片字号/内边距会**跟着桌宠一起缩放**（1.4 倍桌宠时卡片约 1.24 倍），
    大桌宠不会配一张小卡片；不想要可以在设置里关掉「卡片跟着桌宠一起放大」。
* **圆角**：`border-radius: 16px` 加在**最外层** `.card-bg` 上，并且 `overflow: hidden` +
  `clip-path: inset(0 round 16px)` 强制裁剪，圆角外是**真正的透明像素**（桌面壁纸直接透出来）。
  实测：深色 / 浅色背景下四个角都干净（截图取色确认，圆角外是背景而不是卡片底色）。
* **两种外观，可以随时切着对比**（设置 → 进度卡片外观，切完立刻生效）：
  * **最初版本：半透明 + 模糊浮层** —— `rgba(18,22,33,0.88)` + `backdrop-filter: blur(6px)` +
    16px 圆角 + 柔和投影，就是第一版的观感。
    （提醒一句原理：桌宠窗口是"色键透明"，窗口内的半透明像素会和键色有一点点混色，
    所以它看起来会比独立窗口那版稍微"灰"一点 —— 这是这套透明方案的固有代价。）
  * **简洁版：实色卡片** —— 完全不串色，颜色最准，代价是没有半透明感。
* **不会压住角色**：卡片高度由内容撑开，角色缩放按**卡片实测高度**来算；
  窗口比较小时卡片自动转紧凑（只留状态 + 任务名），窗口极小（< 180px 高）时干脆不显示并提示。
  实测三种窗口尺寸下都**没有重叠**。
* 进度卡片固定使用当前已验证稳定的“画在桌宠窗口里”方式；原来的“渲染方式”选项已经移除。
* 打开方式：**右键桌宠 → 显示 / 隐藏任务进度**，或者设置窗口里的「展开 / 收起进度卡片」。
  **开着 / 收起的状态会记住**（`pet_settings.json` 的 `cardOpen`，`remember_card_open()`，
  2026-10-11 加）：关掉桌宠前卡片是开着的，下次启动就自动展开；之前收起的，重启后保持收起。

   卡片里的「打开 Codex」会把你正在用的 Codex 窗口切到前台（按进程识别，不依赖窗口标题）。

## 设置窗口

双击桌宠就能打开，也可以右键 → **设置…**。改完点右下角「保存并应用」才生效（想放弃就点「放弃更改」）：

* **每一栏标题右边的圆圈按钮（↻）**：只把这一栏恢复默认；整页恢复默认在右下角。
* **微红色的一项**（**开机自动启动**）是特意标出来提醒你别乱关的；
  它保存后真的会生效（往启动文件夹放一个快捷方式）。

* **外观**：
  * **桌宠大小**：从 **30%** 到 **160%**（屏幕矮的机器会按屏幕高度兜底），
    滑条两端会显示当前机器的实际范围
  * **不透明度**：40%–100%
  * **视线跟随范围**：0（关闭）到 1200 px，默认 320 px
  * **表情自动切换速度**：2–60 秒换一次
  * 是否始终置顶、是否显示状态小标签
  * 提示：**鼠标滚轮**也能直接缩放，不用每次开设置
* **行为**：是否跟随虚拟桌面、是否开机自动启动；一键「展开 / 收起进度卡片」「让它做个动作」
  「回到右下角」「切到 Codex 窗口」
* **状态对应的表情**：9 个状态各自用一个下拉框选表情（模型里的 40 多个表情都能选），改完立刻换
* **排查**：打开运行日志、打开程序文件夹、重新载入形象、退出桌宠、恢复默认

设置存在 `pet_settings.json` 里，删掉它就回到默认。

关掉桌宠：右键 → 更多 → 退出桌宠，或者双击 `停止桌宠.cmd`。
想重启（改完设置想让它彻底重来）：双击 `重启桌宠.cmd`。

## 它不是一个只会按状态摆表情的木头

### 这个模型里有多少东西

* **表情 44 个**（`.exp3.json`），状态映射 + 随机心情都用它。
* **动作 8 个**，分三组：

  | 组 | 动作 | 时长 |
  | --- | --- | --- |
  | Idle（闲置） | idle.motion3.json | 4.0s |
  | Idle（闲置） | aidale.motion3.json | 4.8s |
  | Tap（被戳） | 自拍简单 | 1.3s |
  | Tap（被戳） | 开盖 | 1.0s |
  | Tap（被戳） | 喷水 | 0.5s |
  | Tap（被戳） | chuipaopao（吹泡泡） | 5.0s |
  | Show（表演） | 自拍 | 3.3s |
  | Show（表演） | 番茄酱 | 5.0s |

  > 这些动作文件里都标着 `Loop=True`，尤其那个 **4 秒的 idle 本身就是一段"表演"**
  > （砸头 / 吹泡泡 / 自拍这些都在里面），所以它会 4 秒一轮不停地重播 ——
  > 之前你看到"老是重复同一个画面"就是这个原因。

### 播放规则现在都能调

设置 → **动作与表情播放**：

* **自动切换表情**——关闭后只显示“状态对应的表情”，不会再随机换脸。
* **表情最短保持时间**（2–60 秒）—— 到点后才允许考虑切换；再配合“到点后真的换表情的概率”控制频率。
* **顺带做个动作的概率**（0–100%）—— 换表情时顺便播一个动作的几率。
* **自动播放动作 / 闲置表演**——关闭后会立即停止正在播放的循环动作，保持呼吸/物理但不主动表演；
  **闲置动作间隔**（0–120 秒，**0 = 完全不做闲置动作**）是它开启时的补充控制。
* **动作白名单**：8 个动作逐条勾选（带组名和时长），**不想看的直接取消勾选**，
  比如把 `Idle · idle.motion3.json` 关掉，就再也不会砸头/吹泡泡了。
  还有「全选动作 / 全部关掉」两个按钮。
* **动作最小间隔**（0–60 秒）—— 两次动作之间至少隔这么久，避免连播。

### 表情也能逐条关掉（重要）

**先说结论**：那个"大锤砸头"其实是**藏在 `idle.motion3.json` 这段闲置动作里的道具动画**。
这个文件有 89 条曲线，其中 **75 条是道具曲线**（`maoshou2..7`、`j2..j7` …），
也就是这段 4 秒动画本身在轮播一堆道具/特效。所以：

* **关表情白名单没用**（它不在表情里）；
* **正确做法**：设置 → **动作白名单** → 取消勾选 **`Idle · idle`**（那条 4 秒的表演），
  只留 `Idle · aidale`（它只有 5 条道具曲线，安静得多）；
* 或者干脆按 **「让它安静点（只保留呼吸）」**：一键关闭自动表情、自动动作和视线/头部跟随，
  停掉正在循环的动作，只保留状态表情与呼吸/物理。

设置里的**表情白名单**仍然有用 —— 这个模型的表情里有不少也是"道具 / 贴纸"类型
（只改一个自定义参数就冒出一个道具，比如 `晕晕`、`吐魂`、`流汗`、`问号`、各种贴纸）：
不想要的在那里取消勾选，状态映射、随机心情、双击换表情都会跳过它。

### 道具动画已经移除

初次制作时无法稳定解决锤子重复问题，因此锤子及相关道具曲线已经从动作文件中删除；
原来的「道具屏蔽」设置也一并移除，恢复用的脚本与备份也已清理。

### 设置改成"点保存才生效"

设置窗口底部现在是：**放弃更改 / 保存并应用 / 恢复默认**，改动的控件会显示
`● 有未保存的更改`，按 **Ctrl+S** 也能保存。桌面上的「保存并应用」按钮在没改动时是灰的。
「让它安静点」「恢复默认」这类按钮也只是**填好表单**，同样要点保存才真正生效。

> 设置窗口顶部现在有一行**实时状态**：
> `桌宠此刻：表情 X · 最近动作 Idle:0 · 白名单已允许 动作 5/8、表情 41/44`
> ——改完设置对照这一行，就能确认到底生效了没有、以及那个讨厌的画面来自哪一个动作。

* 白名单里列出**全部 44 个表情**，取消勾选 = 再也不会出现（状态映射、随机心情、双击换表情都会跳过它）。
* 也有「全部允许 / 一个都不换」两个按钮。
* 同一个页面里「状态对应的表情」下拉框现在能正常列出 44 个表情了 ——
  之前显示"找到 0 个表情"、下拉只有「不改变表情」是**读取路径的 bug**（表情声明搬进
  `FileReferences` 之后，读取代码还在读外层），已修。

* **眼神跟随（按比例映射）**：把鼠标相对**窗口中心**的偏移换算成比例
  `ratio = 偏移 / (窗口宽或高 ÷ 2)`，夹在 `[-1, 1]` 后写进 `ParamEyeBallX/Y` 和 `ParamAngleX/Y`
  —— 鼠标移到窗口边缘时眼珠正好到极限，窗口大小怎么变都对应得上。
* **死区**：比例绝对值小于 `0.1` 时不动，避免手抖眼珠乱颤。
* **平滑**：每帧向目标靠近 10%（Lerp），眼神是"滑"过去的，不是瞬移。
* **范围限制**：超出设定的跟随范围（默认 320 px）就回到中位，不会隔着半个屏幕盯着你看。
* **缩放即同步**：窗口一变大变小，网页下一帧就用新的宽高当分母，同时 Live2D 会收到窗口尺寸变化重新布局。
* **随机心情**：开启“自动切换表情”后，每个状态都有一“池”表情（比如执行中是「开心兴奋 / 喵喵手 / 星星眼 / 调皮 / 魔爪」）；
  关闭后只显示状态对应表情，避免表情频繁跳变。
* **拖动反应**：开始拖的时候随机切换心情（开心、调皮、害羞、生气…），放下之后再补一个反应。
* **戳一下**：单击展开进度卡片时会顺手做个动作、换个表情。
* **被盯着看**：鼠标停在它身上超过几秒，偶尔会脸红或心跳。

## 缩放与大小限制

* **鼠标滚轮**：光标在角色身上滚动即可缩放；也可以在设置里拖「桌宠大小」滑条。
* **锚点**：缩放以**窗口中心**为锚点，不会缩放时"飞走"。
* **范围**：最小 **30%**（2026-10-11 从 12% 抬上来的，再小基本看不清），最大 **160%**。
  （窗口允许比屏幕高出 20% —— 上方那块是空的、留给进度卡片，角色本身贴着底边画；
  屏幕特别矮的机器会按屏幕高度自动往回收一点。）设置界面里的滑条两端就是按你屏幕算出来的实际百分比。
* **冲突保护**：缩放的 0.45 秒内不接受拖动，避免"又缩又拖"打架。

> 顺带一提：透明窗口 + 网页控件在 Windows 上有个坑 —— 鼠标点击会落在窗口本身、传不到网页里。
> 所以桌宠是"程序自己盯着鼠标"来判断你在点它、拖它的，网页只负责演。这样不管系统怎么变都能用。

这些都在 `web/pet.js` 顶部：`MOOD_POOLS`（每个状态的表情池）、`DRAG_MOODS` / `DROP_MOODS` /
`POKE_MOODS` / `SHY_MOODS`，想加表情往数组里填名字就行。

> 如果快捷方式或 `启动桌宠.vbs` 没反应，改用 **`启动桌宠.cmd`** —— 它会显示找不到 Python 之类的具体原因；
> 也可以用 **`诊断.cmd`** 自查。

## 它怎么知道 Codex 在干什么

只读 Codex 自己写的本地文件，不联网、不上传：

* `~/.codex/thread_history_1.sqlite` —— 每个回合的状态（进行中 / 已完成 / 被打断）、每个步骤的类型和时间
* `~/.codex/state_5.sqlite` —— 任务标题、工作目录、token 用量
* `~/.codex/sessions/**/*.jsonl` —— 事件流，用来判断某个工具是否还在跑

桌宠只挑你最近那个"用户任务"，内部子任务（例如安全审阅）不会顶掉它。

### 多 Agent：选谁读谁（2026-10-06 加）

`run.py` 的状态循环不再直接调 `codex_state`，而是走 `agent_state.snapshot(agent_id)`；
设置里「接入的 Agent」选中的 id 存在 `pet_settings.json` 的 `agent` 键里。每个 agent 一个适配器：

| id | 读什么 | 特点 |
| --- | --- | --- |
| `codex` | `~/.codex/` | 原 `codex_state.py`，桌面版和 CLI 共用记录 |
| `claude` | `~/.claude/projects/**/*.jsonl` | 会话 JSONL：user / assistant（含 tool_use）/ tool_result 三段式 |
| `gemini` | `~/.gemini/tmp/*/chats/session-*.jsonl` | 一行元数据 + 逐条 append 的消息记录，`$set` 是元数据更新 |
| `openclaw` | `~/.openclaw/agents/*/sessions/*.jsonl` | 记录还没有时退化：数据文件新旧 + 进程在不在 |
| `hermes` | `%LOCALAPPDATA%\hermes\state.db` | SQLite：`sessions`（标题/工具数/token/最后活动）+ `messages`（最后一句） |

约定和细节：

* 快速切换：右键菜单「切到 X 窗口」下面是「切换卡片 Agent」—— 左键点开一个独立小面板
  （`open_agent_picker()` / `build_agent_picker()`，样式照抄设置页的 Agent 格：当前项预选、
  点选变色、底部「取消 / 确认」）。「确认」才走 `switch_agent()` 写回同一个 `agent` 键并
  `push_settings()`，随后立刻重读一份状态（`refresh_card_after_switch()`），卡片马上换过来。
  面板尺寸约是设置页格子的 0.7 倍；落点由 `agent_picker_location()` 算 —— 顶在右键
  总菜单刚弹出来的地方（`show_menu()` 把菜单真实落点记进 `self._menu_pos`，菜单一
  消失面板就顶上来），贴屏幕右边/底部时夹回工作区，保证整块可见（2026-10-11 定的，
  别放屏幕中间或者贴着桌宠乱猜，菜单在哪面板就在哪最省心）。
  别用右键菜单的子菜单做这件事：① WinForms 子菜单**悬停就自动展开**；② 桌宠的鼠标钩子把
  "点在子菜单里"当成"点在菜单外面"（子菜单是独立弹出层，不在主菜单矩形里），那一下只会
  ReleaseCapture + 关菜单，子菜单项的 Click 永远不触发（2026-10-11 实测"点了没反应"）。
* 名字规则：只接了 CLI 的 agent 下拉框里写「… CLI」；桌面版与 CLI 共用记录的（Codex）不写，
  也不显示"有没有读到记录"的提示。
* 状态翻译统一在 `_finish()`：工具没返回 → 执行中；用户刚发完 → 思考中 / 等待你；
  助手刚说完 → 完成了（90 秒）→ 空闲；记录里最近有错误/打断 → 出错了/被打断。
* 进程兜底用 `tasklist`（可执行文件名）+ `Get-CimInstance Win32_Process`（Node 系 CLI 看
  `node_modules` 包路径，CIM 不可用时退回 `Get-WmiObject`）。只匹配限定在 `node_modules`
  的正则，避免"项目目录碰巧叫 openclaw"这类误判。
* 状态桥：`~/.codexpet/status/<agent>.json`（3 分钟内有效），覆盖在本地记录解析结果上，
  任何 agent 都能用它补任务名 / 工具数；写入器是 `status-bridge.py`。

## 排查

* 双击 **`诊断.cmd`**：会启动一次自检，把 `pet.log` 打出来，并导出一张 `selftest.png`。
* **点「设置…」没反应？** 现在设置窗口会：① **置顶**显示（不会被 Codex 窗口压住）；
  ② 在**任务栏**留一个图标（找不到时可以点出来）；③ **自动搬到你现在看的虚拟桌面**
  （新窗口默认开在"进程启动时那个桌面"，切过桌面就会看不见 —— 这是之前那个 bug 的原因）。
  ④ 设置窗口跑在**独立的 STA 线程**上 —— 之前它是在右键菜单回调里直接建的，
  那条路径上线程被当成 MTA，WebView2 会报
  `RPC_E_CHANGED_MODE：无法在设置线程模式后对其加以更改`（就是那个弹窗）。
  日志里会写 `打开设置窗口…` / `设置窗口 WebView2 就绪…` / `设置窗口初始化失败…`，一看就知道卡在哪一步。
* **设置窗口最小化到任务栏后，再点「设置…」没反应？**（2026-10-11 修）以前只调
  `Activate()` / `BringToFront()` —— 对**最小化**的窗口这两个都不生效，它会一直躺在任务栏里。
  现在 `restore_settings_window()` 先把 `WindowState` 设回 `Normal`、被 Hide 过就 `Show()`、
  再搬回桌宠所在的虚拟桌面并置前；整套动作丢回设置窗口自己的 STA 线程执行
  （跨线程操作 Form 必须回到它自己的线程）。
* **设置窗口的大小/位置**（2026-10-11 加）：用户摆好之后（`ResizeEnd` / 关窗时）写进
  `settings_window.json`，下次打开先 `fit_window_rect()` 夹回工作区再套用 ——
  关了再开不会回到初始的 580x680，换显示器/改分辨率也不会跑到屏幕外。
* 日志文件：`pet.log`（每次启动都会追加），里面会记录：
  * 鼠标事件（`鼠标事件：pat (123,456)` 这种），能看出点到底有没有被识别
  * 每次拖动：用时、**搬动次数与速率**、位置变化、渲染 FPS
  * 渲染 FPS：约每分钟一条（含窗口尺寸和缩放）
  * 页面加载、WebView2 初始化结果、设置变更
  * **未捕获异常**：桌宠是 `pythonw` 启动的（没有控制台），异常以前会凭空消失，
    现在会连同堆栈一起写进日志 —— 出问题时先看这里
* **滚轮缩放后偶尔留一块黑边？** 这是 Win11 对"挖空背景的透明窗口"改尺寸时不重画旧区域的
  老毛病（切一下别的窗口、拖一下桌宠也会自己掉）。现在每次改完尺寸都会自动连着重画几次
  （约 1.2 秒内 9 次，最后一轮还会把窗口抖 1px 逼系统重新合成），把概率压得很低；
  万一还留着，**右键桌宠 → 重画窗口（缩放后出现黑边时点一下）** 立刻就能清掉。

## 左键：按下即捕获（别让下面的窗口先接住）

桌宠窗口对鼠标是全穿透的，所以左键按下会被**下面的窗口**先收到：在 Codex 里按住桌宠拖动，
正文文字就被框选了 —— 因为等 33ms 轮询发现"在拖动"、再去 `SetCapture` 时，下面那家
已经开始框选。

现在改成在**鼠标钩子里**（`WH_MOUSE_LL`，早于消息投递）判断：`WM_LBUTTONDOWN` 且
`click_on_pet()`（像素在角色上 + 光标在窗口矩形内）→ 立即 `SetCapture(桌宠窗口)`。
于是这次左键（包括只点一下不拖）**根本不会投给下面**，既不会框选也不会误点下面的按钮。

三条必须记住的：

1. **只捕获、不吞事件**。吞掉（钩子返回 1）会让 `GetAsyncKeyState` 读不到这次按键，
   轮询出来的点击/拖动就全哑了 —— 右键走"吞"那条路时踩过这个坑，所以右键才不得不把
   整条链路搬进钩子；左键没这个问题，捕获就够了。
2. 抬起（`WM_LBUTTONUP`）立刻 `ReleaseCapture`；`on_tick` 里还有一道兜底：
   发现左键已经松开却还抓着，就放掉 —— 绝不能让鼠标被桌宠一直抓着。
3. 判据不满足（透明处 / 像素判定没就绪 / 取光标失败 / 还没有窗口矩形）**一律不抓**，
   那些点击本来就该穿过去。

## 卡片：重新载入 vs 刷新

* **重新载入形象**（`reload_page`）是 `CoreWebView2.Reload()`，整页重来 —— 页面里的卡片状态
  回到默认的“收起”，所以以前重载完卡片就消失了。现在网页报 `ready` 时，宿主会按自己的
  `inline_card_open` 补发一条 `{t:"card", open:…}`，卡片状态跟着宿主走，重载前后一致。
* **刷新卡片信息**（`refresh_card_now`）只重读一次 `codex_state.snapshot()` 直接推给页面，
  绕过 `state_loop` 的“每秒一次 + 内容没变不重发”去重；卡片关着就先打开。
  只刷数据，不碰模型 —— 跟“重新载入形象”是两件事，别混。

## 卡片底部的用量显示

`usage_stats.py` 负责算，`run.py` 的 `state_loop` 每秒问一次，把结果塞进 payload 的
`usage` 字段，网页那边只是把它写到 `#card-usage`（`pet.css` 里 `.card-foot` 做成一行两格）。

两种模式（设置项 `usageMode`）：

* `today` **今日新增** —— 今天（按**本地**日期）所有已接入 agent 的 token 增量合计；
* `session` **本会话累积** —— 当前会话的累计消耗；
* `off` 不显示。

关键坑（别踩第二次）：Codex 会话里的 `total_token_usage` 是**会话级累计**（每个会话各自从 0 涨），
所以"今天用了多少"**不能**把各会话的数值直接相加。正确算法是——对每个会话取
"今天最后一条的值 − 今天第一条的值"（跨天会话也就算对了），再把所有会话加起来。
时间戳是 UTC，比较前要折成本地日期，否则北京时间早上 8 点前的记录会算到前一天去。

开销：冷启动扫一遍全部会话约 200 ms，之后每个文件的增量按 mtime 缓存；
外加 20 秒节流（`REFRESH_SECONDS`），活跃文件重扫只要 ~17 ms，所以每秒问一次也没负担。
多 agent 已经预留在 `_AGENT_TODAY_READERS` / `_AGENT_SESSION_READERS` 里，
接入新 agent 时加一行读者函数，"今日新增"就会自动把它的量算进去。

## 渲染频率

早期版本把 `maxFPS` 设在了 `app.ticker` 上，而页面用的是共享 ticker（`sharedTicker: true`），
所以那个上限其实**没生效**（日志里能跑到 300+ 帧）。

现在改成 **设置里的「渲染帧率上限」**（`fpsLimit`，默认 60，可选 30–240 或"不限制"），
由 `applyFpsLimit()` 同时设到 `PIXI.Ticker.shared` 和 `app.ticker` 上；实测上限 30 / 90 / 60 时
真实渲染帧数是 29 / 86 / 59 fps，"不限制"时 149 fps（见 README 的「性能实测」）。
另外 `countFrame()` 挂在共享 ticker 上自己数帧，设置页显示的"当前 fps"用的就是这个值 ——
PIXI 自带的 `ticker.FPS` 是平滑值，刚改完上限时会虚高（实测偏差能到 60%），不能直接拿来显示。

另外，早期版本为了让右键菜单更精准，每 120 ms 读一次整块画布像素 —— 那会让 GPU 流水线停顿，
所以删掉了。删掉之后“点在不在角色身上”只能按**角色包围盒**判断，于是包围盒里的透明缝隙
（发丝之间、手臂和身体之间、两条腿之间）会“既穿过去、又当成点中了角色”：右键同时弹两个菜单、
拖动顺带点到下面的窗口，都是这么来的。

现在换成**按需、单像素**的采样（`web/pet.js` 里的 `probe`）：

* 一次只读光标底下那 1 个像素，~20Hz；
* **光标不在窗口里就完全不读**，所以平时开销是零；
* 采样挂在 `renderer.render` 返回**之后** —— 画布没开 `preserveDrawingBuffer`，在渲染之前读
  只会读到空帧（实测：挂在 `PIXI.Ticker.shared` 默认优先级上永远读到 0，那样会把点击全禁掉）。
  结果用 `{t:"over"}` 报给宿主，`on_character()` 就用它决定这次点击/拖动归谁；
* 万一读不出来（异常），会报 `{t:"over-probe", value:false}`，宿主自动退回包围盒判断，
  不会因为探测坏了把桌宠点不动；
* 拖动开始时 `SetCapture` 把鼠标捕获在桌宠窗口上，松手那下不会再落到光标底下的窗口/图标上；
  只有“这次按下确实判在角色身上”（像素探测可用，或系统真的把事件发给了桌宠窗口）才会去捕获。

* 一次点击要求**按下和松开都压在角色像素上**：在角色边缘按下、挪到旁边的透明处再松手，
  以前就会“桌宠弹菜单 + 桌面也弹菜单”，现在两边都不算；
* 光标一移动就跟着渲染帧采样（停住之后才改成低频复检），把“刚移开就按下”的滞后压到 1 帧内；
* 宿主会用 `WindowFromPoint()` + `GetAncestor(GA_ROOT)` 记一条“这个点系统认为归谁”的诊断
  （只在“像素判定和系统判定不一致”时写日志）。**只记录、不当拦截依据** ——
  曾经拿它在弹菜单前否决，结果那台机器上系统对所有点都答“不是桌宠”，右键菜单直接全废；
* 鼠标判定从 110ms 的 tick 挪到 33ms 的光标定时器里也跑一遍，按下那一刻的判定更接近真实时刻；
* **在系统分发之前把“点在角色上”的那一次右键吃掉**：`WH_MOUSE_LL` 钩子回调返回 1（毫秒级，
  等 33ms 轮询来不及）。实测这台机器上桌宠窗口对鼠标是**全穿透**的 —— `WindowFromPoint` 在角色像素上
  返回的是 `SysListView32 / root=Progman`（桌面图标层），所以下面那个窗口必然弹出它自己的菜单，
  而且 z 序压在我们的 ToolStrip 菜单上面，看起来就是“只有系统菜单、桌宠菜单没有”。
  吃掉之后：桌面收不到这次右键 → 不弹它的菜单。**注意：事件被丢弃后 `GetAsyncKeyState` 也往往读不到这次
  按键了**（实测就是“系统菜单没了、桌宠菜单也哑了”），所以整条右键链路都放在钩子里自己走完：
  按下记位置、`WM_MOUSEMOVE` 跟踪移动量、抬起时若几乎没动就把“待弹菜单”交给 33ms 的光标定时器去弹。
  菜单弹出时记 `_menu_shown_at`，0.25s 内不重复弹（轮询路径万一也判到同一次右键，不会弹两遍）；
* **菜单开着时，左键点在菜单外面 = 一次点击既关菜单、又照常落到桌面**：鼠标钩子在事件分发前
  判断"左键按下 + 点在菜单矩形之外"，先 `ReleaseCapture()`（ToolStrip 的鼠标捕获一放，
  这次点击就不会被菜单吃掉），再给桌宠窗口 `PostMessage(WM_PET_CLOSE_MENU)` 让菜单在消息循环里
  关掉（钩子回调里不直接调 .NET），最后 tick 里再兜底 `Close()` 一次。
  ——ToolStrip 默认行为是"点外面只关菜单、这一下点击被吞掉"，要点两次才生效；
  改成这样以后，想取消菜单只需点一下桌面，而且那一下是正常点击（不会误触菜单项、也不用点第二次）。
  * 关闭请求一定要带**时效**（`_menu_close_at`，1 秒后作废），而且新菜单弹出、菜单关闭时都要清零：
    否则"点外面关闭"那一次留下的请求会活到下一次，把刚弹出的新菜单立刻关掉 ——
    表现就是**第一次右键菜单闪一下就消失、第二次才正常**（已踩过一次）。外面点关闭的消息
    （`WM_PET_CLOSE_MENU`）同样要校验时效，晚到不能误关新菜单。
  * 钩子路径**每次右键都弹菜单**（不能加"0.25s 内不重复弹"这种去重，连点会漏）；
    去重只留给轮询兜底路径，避免同一次右键被弹两遍。
  * `on_menu_closed` 里如果发现菜单存活 < 0.6s，会记一行
    「右键菜单刚弹出就关闭了（存活 x.xx s）」，以后再出现闪退直接看日志。
  * **菜单和底层判定必须互斥**（踩过一次）：菜单是独立浮层，但底下的轮询看的是
    "光标坐标落在角色包围盒的哪个命中带里" —— 菜单正好浮在橡皮擦上方时，
    点"重新载入形象"就会连带触发一次橡皮擦。现在三处一起挡：
    1) `handle_mouse()` / `on_mouse_event()` 见到 `_menu_visible` 直接返回，
       顺带清掉排队中的单击（`pending_single`）；
    2) `on_menu_closed()` 里开 0.35 秒**忽略窗口**（`_ignore_click_until`）——
       点菜单项会让菜单立刻关闭，等 33ms 后轮询跑起来时菜单已经不可见，
       光靠 `_menu_visible` 挡不住那一下；
    3) 菜单开着时右键不再被钩子吞掉/重弹（交给菜单自己处理），
       点菜单外面关闭时也进同一个忽略窗口（那一下属于桌面/下层窗口）。
  判据：像素结论 `over_char` 为真 **且** 光标在桌宠窗口矩形内（`_rect_cache`，钩子里只读缓存），
  两个条件都满足才吞，避免误吞你在别处的右键。
* 点击判定改成“按下/松开两个时刻一起看”：原地点击只要任一时刻判在角色上就算（按下那一瞬间的像素结论
  可能比网页采样慢半拍，只认它就会出现“右键点在角色上却没反应”）；有位移时要求两头都在角色上。

下面两条跟渲染频率没关系，顺手记在这里：
* 看不到形象时先确认：是不是被别的最上层窗口挡住了 / 是不是禁用了 WebView2 运行时
  （Windows 10/11 一般自带 "Microsoft Edge WebView2 Runtime"）。
* 启动器找不到 Python 时，设置环境变量 `CODEXPET_PYTHON` 指向 `python.exe` 即可。
